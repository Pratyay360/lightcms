## Self-hosting

Want LightCMS fully under your control? It's a pure SvelteKit app, so it runs
anywhere SvelteKit does — Netlify, Vercel, Cloudflare Pages, Deno Deploy, or
your own server. I recommend [mise](https://mise.jdx.dev) for managing the dev
env.

For deployment options, see the
[SvelteKit adapters documentation](https://svelte.dev/docs/kit/adapters).

### 1. Run the github bot setup

```bash
mise run bot
```

This walks you through creating a GitHub App via probot. If everything  
completes successfully, you'll have a `.env` file in your current working  
directory.

### 2. Configure environment variables

```env
BETTER_AUTH_SECRET=""
BETTER_AUTH_URL="https://your-domain.example"
DATABASE_URL="postgresql://user:password@host/database?sslmode=require"

# GitHub Credentials — Generated by the Setup Bot
GITHUB_APP_ID="your-app-id"
GITHUB_APP_NAME="your-app-name"
GITHUB_CLIENT_ID="your-client-id"
GITHUB_CLIENT_SECRET="your-client-secret"
GITHUB_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\n...\n-----END RSA PRIVATE KEY-----"
GITHUB_WEBHOOK="https://your-webhook-endpoint.example"
GITHUB_WEBHOOK_SECRET=""

CDN_URL=""
CDN_KEY="" #any chevereto compatible. endpoint

MAIL_FROM="newsletter@example.com"
MAIL_HOST="smtp.example.com"
MAIL_PASS="your-smtp-password"
MAIL_PORT="465"
MAIL_SECURE="1"
MAIL_USER="smtp-user"

# Optional AI configuration
OPEN_AI_ENDPOINT="https://api.openai.com/v1"
OPEN_AI_APIKEY="your-api-key"
OPEN_AI_MODEL="your-model"
```

- `BETTER_AUTH_URL` must match the public URL the app is served from. For local
development, use `http://localhost:5173`.
- Generate secrets locally and never share them:
  ```bash
  python -c "import secrets; print(secrets.token_hex(32))"
  # or
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  # or
  openssl rand -hex 32
  ```

For more details, see the
[Better Auth installation guide](https://better-auth.com/docs/installation).

### 3. Set up the database

LightCMS uses PostgreSQL. You can use a managed provider such as
[Neon](https://neon.com), [Nile](https://thenile.dev), or [Supabase](https://supabase.com) — see
[awesome-free-postgres](https://github.com/alexeyfv/awesome-free-postgres) for
free options — or run PostgreSQL yourself. Only use a provider you trust, and
keep the connection string in your environment variables.

After setting `DATABASE_URL`, generate and apply migrations:

```bash
npx drizzle-kit generate
npx drizzle-kit migrate
```

Prefer generated migrations for shared or production databases. Use
`npx drizzle-kit push` only on a development database when you intentionally
want to sync the schema directly:

```bash
npx drizzle-kit push
```

If something fails or the schema looks out of sync, inspect the current state
first:

```bash
npx drizzle-kit introspect
```

Never run destructive commands against production without a backup and a review
of the generated SQL.

### 4. Configure GitHub

Create a GitHub App and copy its App ID, client credentials, webhook secret,
and private key into the environment. Grant only the repository permissions
your workflow needs, and subscribe the app to the events LightCMS handles.

The private key must preserve its line breaks. If your platform requires a
single-line value, encode the newlines in the format that platform supports
and decode them in the app config. The
[private-key formatter](https://www.samltool.com/format_privatekey.php)
can help check formatting, but never paste a production key into a
third-party service.

For local webhook testing, tunnel with [smee.io](https://smee.io/) and point  
`GITHUB_WEBHOOK` at the tunnel URL. In production, use your deployment's  
permanent HTTPS URL.

### 5. configure cdn

Any [chevereto](https://chevereto.com/) compatible instance you can use any instance, some free options are 

1. [https://imgcdn.dev/](https://imgcdn.dev/)
2. [https://shareimg.eu/](https://shareimg.eu/)
3. [https://freeimage.host/](https://freeimage.host/)
4. [https://imgbb.com/](https://imgbb.com/)

```bash
CDN_URL="https://examplecdn.dev/1/upload"
CDN_KEY="" # api key  
```

### 6. Configure email

LightCMS sends emails via SMTP. To configure this, set the `MAIL_*` variables using credentials from your email provider. For a complete list of available SMTP options, please refer to the [Nodemailer documentation](https://nodemailer.com/message/).

If you own a domain, [Resend](https://resend.com) is the easiest option to set up. Otherwise, [Zoho Mail](https://www.zoho.com/mail) is the most straightforward way to get started.

### 7. Run and deploy

Start your own LightCMS instance by running the development server:

```bash
npm run dev
```

When you're ready, you can deploy to any platform using a [SvelteKit adapter, such as Netlify, Vercel, or Cloudflare](https://svelte.dev/docs/kit/adapters).
